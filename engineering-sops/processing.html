Standard Operating Procedure (SOP)

Document ID: SOP-DE-2026-004 | Target System: Distribution ERP Inventory Core

1. Operational Objective

This document details the recovery loops, schema enforcement rules, and repeatable execution steps for the nightly extraction, isolation, and processing of legacy industrial ERP inventory mutations.

2. Data Lineage Matrix

Data must transition through three isolated storage phases to protect production analytical data warehouses from upstream ledger transactional drift.

|  [Source ERP]     | ---> |  [Isolated Stage] | ---> | [Validated Core]  |
|  Raw Export       |      |  Flat File Ingest |      | Operational Table |

3. Schema Enforcement & Boundary Values

Every inbound file must conform to deterministic structural checks prior to warehouse ingestion. Any record failing these bounds is automatically isolated to prevent corrupting tracking ledgers.

  • File Format Constraint: Fixed-width text format or comma-delimited ASCII text files only.
  • Required Fields: Transaction_ID (String, Alpha-Numeric), Part_Number (String), Mutated_Qty (Integer), Unit_Cost (Decimal).
  • Boundary Intercepts: If a row contains a Mutated_Qty exceeding physical warehouse storage capacities or an unverified negative value, the engine halts automation and moves the entry to a manual verification queue.

4. Recovery & Backfill Protocol

When an upstream source failure drops a connection mid-extraction, follow this sequence to perform a clean, non-duplicate run:

  1. Flush Target Staging: Run an explicit purge on the temporary staging tables for the target date to ensure zero partial duplicate blocks exist.
  2. Verify Source File Integrity: Inspect the structural timestamp on the isolated backup directory to confirm the raw file export was successfully re-driven by the distributor server.
  3. Re-execute Batch Automation: Execute the procedural extraction script directly from the terminal console using the manual date parameter flag.
